# M6 retro — Multiplayer MVP

**Estimated:** ~30h. **Actual (this session):** ~3h wall-clock.
**Status:** DONE per STANDARDS.md §2.1. Client prediction / reconciliation (M6.5), chunk streaming (M6.6), remote-player avatars (M6.8), and host-migration (M6.11+) deferred to backlog.

## Shipped

- `src/net/codec.ts`: bit-packed binary Writer/Reader + 5 message types (HELLO, CHAT, BLOCK_EDIT, PING, PONG). LEB128 varints, 2-byte length-prefixed UTF-8 strings, bounds-checked reads.
- `signaling/server.ts`: ~260 LoC Node+ws WebSocket relay. Room codes from a 32-char phone-friendly alphabet, 8 peers/room, 30 msg/s rate limit, 10-min idle sweep, health endpoint, Docker-packaged.
- `src/net/transport.ts`: Transport interface + `RelayTransport` (WS-relay fallback) + `WebRTCTransport` (two DataChannels: reliable+ordered for edits/chat, unreliable+unordered+0-retrans for 30Hz telemetry).
- `src/net/SignalingClient.ts`: typed WS wrapper with onRoom/onJoined/onPeerJoined/onPeerLeft/onSignal/onError/onClose events. Factory-injectable socket for tests.
- `src/net/PeerNegotiator.ts`: W3C perfect-negotiation pattern over `RTCPeerConnection`; impolite/polite roles resolve offer collisions deterministically.
- `src/net/MPSession.ts`: host-authoritative message dispatch. Host broadcasts local edits + rebroadcasts foreign ones to everyone else; guests send to host; chat flows through an `onChat` callback.
- `src/net/RoomClient.ts`: high-level orchestrator combining signaling + negotiator + session under `createRoom()` / `joinRoom(code)`.
- `main.ts` integration: `?mp=create` / `?mp=CODE` URL flags. HUD appends `room ABC123` when connected.
- e2e `m6-multiplayer.spec.ts`: two browser contexts complete the full create → signal → join handshake; both HUDs report the same 6-char room code.

## Cut or deferred (to backlog.md)

- **Client prediction + reconciliation** for position/entity telemetry (M6.5). Block edits are already consistent because they're host-authoritative + reliable; smooth remote-player movement needs snapshot interpolation that doesn't yet exist because there are no remote-player avatars to move.
- **Chunk streaming on join** (M6.6). New guests currently see only their locally-generated world; no CHUNK_FULL/CHUNK_DELTA messages yet. Host and guest diverge on chunks the host has edited before the guest generated theirs.
- **Remote-player avatars + chat UI** (M6.7, M6.8). Chat hits the console today; a DOM text stream and on-screen capsule avatars are next.
- **Rate limiting + packet-size validation on the client** (M6.10). Server rate-limits already; client-side decode cap in the codec rejects ridiculous block-edit counts, but per-message-type validation is minimal.
- **Host-migration** (M6.11+). Host-leave today just drops the session; picking a new host + transferring world state is a real engineering task.

## Biggest surprise

Playwright's `webServer` config supports an array — I didn't realize that until I needed to boot both Vite and the signaling server for the multiplayer e2e. Made the whole test work with zero test-level setup code.

Second surprise: TypeScript's `exactOptionalPropertyTypes: true` makes passing `{ onChat: undefined }` into an object literal type error out, even though the runtime behavior is identical. Had to gate the spread with `...(this.onChat ? { onChat: this.onChat } : {})`. Recurring enough across M5 and M6 that it's probably worth a helper.

## Next milestone (M7) should know

- `MPSession` currently only syncs block edits + chat. Entity state (mobs, dropped items, XP orbs in future) will need a new message type and a snapshot protocol. Design lands alongside M11 (extended mobs) since M7's 3 mobs can be host-authoritative without prediction.
- Chunk-streaming on join (M6.6 deferred) becomes visible in M7 the moment a guest joins a host who has already crafted a chest — the chest voxel is missing from the guest until it generates the chunk. Fix before shipping M7 multiplayer.
- Block-edit dedupe: M6 emits every edit from both the world-set path and the interaction callback. Fine today because `world.set` is idempotent and block-edit messages include an absolute position, but M7's crafting-grid edits (sub-block state changes) will need a proper tick-indexed stream.
