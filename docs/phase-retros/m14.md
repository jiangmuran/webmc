# M14 — End (Retrospective)

## Shipped

- **4 end blocks**: end_portal (light 15, hardness -1), dragon_egg (solid non-opaque), purpur_block, end_rod (light 14 non-solid).
- **EndGenerator** — central end-stone disk at y≈60 with radius 80 + a taper function; 10 obsidian pillars placed deterministically around the disk at radii 42–60 with heights 30–52. Uses Perlin `fbm2` for thickness variation.
- **Ender dragon mob def** — 200 HP, 16m×8h×16m box, 10 damage, 128 block aggro. `behavior: 'hostile'` as placeholder; real flight AI + phase machine deferred.
- **Shulker mob def** — 30 HP, static (walkSpeed 0), 2 damage, 16 block aggro. Shulker projectile + levitation deferred.
- **Tests**: island-centre returns end_stone, far-from-island returns AIR, pillars appear somewhere in the 7×7 chunk disk.

## Cut / deferred (to Post-M14)

- **Boss fight loop + crystal healing.** Requires a crystal entity and a phase state machine that the generic `MobWorld` doesn't support.
- **End cities + shulker spawning + elytra loot.** Same cross-chunk structure blocker that's held up M10 mineshafts / villages / fortresses.
- **Stronghold / eye-of-ender.** Overworld side of the End loop; unblocks player entry but needs the same structure coordinator.
- **Dragon flight AI.** Current def is `hostile` ground-chase; flight mode + circling pathfinder is its own subsystem.

## Biggest surprise

The `EndGenerator` was a 70-line file because all the complexity in MC's end island (noise islands, voids, void damage) collapses to "disk + pillars" at our current scope. The harder pieces (dragon fight, elytra) need new subsystems, not more gen code. Separating the block+gen+mob scaffolding from the gameplay mechanics lets both the nether and end ship as trivially-testable modules; the gameplay integration is its own M16+ milestone.

## What the next milestone should know

- **End is fully deterministic** for a given seed — same pillar positions, same disk shape. Useful for e2e tests later.
- **Dragon box** is 16×8×16 — careful when adding collision: it dwarfs the existing AABB sweep which assumes small boxes. If the dragon interacts with terrain, we need a coarser collider (or just not collide at all with terrain, per MC).
- **Exit portal fill** and **credits** are the visible "you won" indicators; for webmc they're content polish, not engine work.
- **Dimension registry** now knows about `'end'` once wired — `DimensionRegistry.translate` with scale 1 handles end coords as a no-op, per MC.
