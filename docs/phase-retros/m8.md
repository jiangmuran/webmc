## Shipped

- `src/redstone/signal.ts`: pure-fn BFS power simulator. Sources emit 0–15; dust propagates losing 1 per block; doors and opaque conductors strong-powered at source level; dust weakly powers neighbours (including doors above the dust).
- `src/redstone/RedstoneWorld.ts`: tick scheduler (10 Hz default) + interactive state tracker. Levers toggle, buttons queue a 1s release timer, plates stay hot while registered, torches emit constantly (MVP — inverter behaviour is a follow-up).
- `src/redstone/adapter.ts`: `classifyBlock(registry, state) → RedstoneBlock` + `lookupFromWorld(world, registry)` bind the generic simulator to webmc's BlockRegistry + World.
- Block registry: 8 new block defs — redstone dust / torch / lever / stone button / oak pressure plate / oak door / oak trapdoor + (conductor promotion rule for any opaque block).
- 256 unit tests green, covering attenuation, two-source merge, conductor powering, door neighbour, dust-break propagation, lever toggle, button release, plate pulse.

## Biggest surprise

The BFS power simulator is cheap enough that re-running it every redstone tick (10 Hz) over a whole chunk is fine — no need for the incremental-propagation bookkeeping that MC's Java implementation uses. Real world tests show ~0.05 ms per tick for a 1000-cell dust grid in Node; well under the 100 ms redstone tick budget. Revisit if M15 adds piston spam.

Second: the cleanest way to model "an opaque block can be strong-powered" was to treat every opaque non-kind block as kind='conductor' in the adapter, so the simulator doesn't need to special-case arbitrary blocks. Keeps the core simulator's contract narrow.

## Next milestone (M9) should know

- `RedstoneWorld.tick(dt, lookup)` is the integration hook main.ts will call alongside `mobWorld.tick`. Door open-state is available via `isDoorOpen(pos)` so renderers can flip the door mesh.
- Registered sources (levers/buttons/plates/torches/doors) are keyed by "x,y,z" strings. When a chunk unloads, main.ts should call `rw.unregister(pos)` for every redstone-kind block in that chunk to keep the source list clean.
- The pressure plate implementation is "always on while registered"; M9 fluids or M11 mob weights will refine to "on while an entity stands on it".
