# M17 — Datapack Loader (Retrospective)

## Shipped

- **DataPack schema** — `{ meta, blocks?, recipes?, loot? }` JSON shape. Meta requires `{ name, version }`; blocks / recipes / loot are optional arrays. Schema is webmc-native; not compatible with vanilla Minecraft datapack layout (different recipe format + no function scripting).
- **`validatePack(raw)`** — shape-checks the input and returns a `DataPack`. Throws on malformed input. Designed to catch the common upload mistakes (missing meta, wrong types).
- **`loadPack(pack, { blocks, items?, recipes? })`** — merges validated pack content into the provided registries; returns a `LoadReport` with counters + per-item error messages. Errors don't throw — duplicate block names, unresolved ingredients, etc. are collected and reported.
- **Shaped + shapeless recipes** are supported. Shaped pattern is a 3-row string array with a `legend` mapping each character to an item name; space = empty slot. Shapeless takes a plain ingredient list.
- **`parsePackJson(str)`** — convenience wrapper for user-uploaded strings.

## Cut / deferred

- **M16 performance milestone** — intentionally skipped. WebGPU, SharedArrayBuffer, shader-smoothing, shadows, thermal throttle each deserve their own run; the session prioritised pure-logic breadth over rendering rewrites.
- **QuickJS-wasm behavior pack sandbox** — needs a ~700 KB WASM dependency. Loader is there when we're ready.
- **Loot table merge.** Pack schema accepts `loot: [...]`; the `loadPack` report counts entries but BlockDropRegistry integration is not wired.
- **Runtime resource-pack support** — M0 brief mentioned MC `.zip` resource packs; still unimplemented (separate from webmc-native data packs).

## Biggest surprise

The RecipeRegistry API expects a 2D pattern of `(ItemId | null)[][]` rather than string rows with a legend. The datapack format uses string-rows-plus-legend because that's human-writable; loadPack converts one to the other. Doing the translation at load time keeps the in-memory recipe format tight and the JSON format readable — don't bleed the optimization shape into the authoring shape.

## What the next milestone should know

- **Pack schema is versioned in `meta.version`** — there's no migration layer yet; a future schema bump needs a `migratePack(from, to, pack)` shim.
- **`loadPack` does not rollback on error.** Blocks registered before a malformed recipe stay registered. The pack is best-effort; user sees errors in the report.
- **Space character in pattern strings = null slot** — do not allow user-chosen characters to shadow this without an escape.
- **Item names are resolved at load time, not match time.** Renaming an item invalidates recipes loaded before the rename — reload packs if your registries mutate.
- **Blocks registered by a pack are permanent** for that BlockRegistry instance — there's no unregister API yet. Reload the world to drop them.
