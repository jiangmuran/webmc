**Estimated:** ~15h. **Actual (this session):** ~1h wall-clock.
**Status:** Partial DONE per STANDARDS.md §2.1. Core mobile input and audio shipped; settings panel (M4.4) and dynamic-quality throttle (M4.3) tracked in backlog.

## Shipped

- `src/engine/input/TouchControls.ts`: drag-anywhere virtual joystick on the left half, look-drag on the right half, three HUD buttons (Break / Place / Jump) thumb-reachable in the bottom-right. Attaches only when `isTouchDevice()` so desktop Chromium keeps keyboard-mouse behavior.
- `src/engine/audio/AudioBus.ts`: Web Audio wrapper with first-gesture unlock (click / touchstart / keydown), three procedurally synthesized sounds (break, place, step), linear distance attenuation from 2 m to 16 m. Zero audio files ship; everything is oscillator + envelope.
- `InteractionController.onBreak` / `onPlace` callbacks wire the audio triggers at the affected voxel.
- `main.ts` swaps the touch vs. keyboard input paths cleanly — only overrides keyboard-set `fp.input.forward/strafe` when the touch joystick reports nonzero motion.
- Playwright mobile matrix (6 scenarios on Pixel-7 emulation) already passing from M1–M3; this milestone adds nothing new to break.

## Biggest surprise

Playwright's Pixel-7 emulation actually fires `touchstart` events, so `isTouchDevice()` returns true under CI. This broke the M1 walkaround test: touch code was unconditionally overwriting `fp.input.forward` to 0, cancelling the keyboard W keypress. Fix: touch input only overrides when its own deltas are nonzero. Lesson for future mobile-emulated tests: treat the two input paths as additive, not switched.

## Next milestone (M5) should know

- Settings persistence when M4.4 lands should share the same `webmc.settings.v1` localStorage key that M5's world selector will also use for 'last seed'.
