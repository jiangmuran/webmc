# M16 — Performance + Platform (Retrospective)

## Shipped

- **`PerfMonitor`** — rolling-window frame-time monitor with adaptive quality state. `tick(dtSec)` feeds each frame; `p95()` reports the 95th-percentile frame time over a configurable window; internal state-machine drops or raises a `quality` value when the threshold is sustained.
- **Adaptive view-distance** wired into `main.ts`: `perfMonitor.tick(dt) → loader.setViewRadius(perfMonitor.quality)`. When p95 sustained above 33 ms for 3 s, view radius drops by 1; when sustained below 22 ms for 3 s, raises by 1. Dead zone between 22–33 ms holds position.
- **8 unit tests**: warm-up no-op, drop on sustained lag, rise on sustained headroom, dead-zone hold, minQuality floor, p95 monotonicity, reset.

## Cut / deferred (Post-M16 backlog)

- **WebGPU backend.** Feature-flagged path + golden-image parity test = its own milestone-sized effort.
- **SharedArrayBuffer mesh workers** — COOP/COEP headers are set to `credentialless` but runtime detection + transfer swap is not in place.
- **Shader-based smooth lighting.** Current lighting is flat per-vertex from the mesher; shader interpolation would re-work `ChunkShader`.
- **Cascaded sun shadows + SSAO + thermal-API hooks.** All shader work + new passes.

## Biggest surprise

The perf monitor's dead zone matters more than the thresholds. Without a gap between `upShift` and `downShift`, the system oscillates: drop a radius → now renders faster → p95 dips below → raise a radius → now renders slow → drop again. With a 22–33 ms band, a sustained 30 ms world renders stably at whatever radius lands in that band. Basic hysteresis — once it was explicit in the API, everything else was boring.

The rolling p95 rather than a running average was also load-bearing: one 100 ms hitch from a chunk mesh shouldn't penalize a steady 16 ms baseline. p95 ignores the worst 5% of frames, so it tracks the "typical-at-worst" quality most closely.

## What the next milestone should know

- **Default startQuality is 6** (matches legacy `viewRadius: 6`). Low-end devices should hand in a lower `startQuality` at construction — there's no runtime probe yet.
- **`quality` is whatever integer metric the caller maps it to.** Today it's `ChunkLoader.viewRadius`; tomorrow it could key into a table of {mesh LOD, texture filter, AO enable}.
- **PerfMonitor resets its "condition start" timer after every quality change.** Don't expect a single 3-second bad run to drop two radii; it takes two 3-second runs back-to-back.
- **WebGPU / SharedArrayBuffer are Post-M16.** When they land, the perf monitor stays — it's renderer-agnostic.
