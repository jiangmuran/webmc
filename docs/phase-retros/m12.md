# M12 — Enchanting / Brewing / Trading (Retrospective)

## Shipped (pure-logic layer)

- **XP curve + progress** in PlayerState: MC formula `2n+7 / 5n-38 / 9n-158` for levels 1–16 / 17–31 / 32+. `addXP`, `spendXPLevels`, and level rollover covered by tests.
- **Status effects** on PlayerState: regeneration, poison, instant_health, instant_damage; effect ticking, decay, and respawn-clear.
- **Enchantment registry** — 7 enchantments (sharpness, efficiency, unbreaking, fortune, silk_touch, protection, power). `applicableFor` narrows by tool kind / item name; `rollEnchantment` is weighted-random by rarity; `applyEnchant` / `hasEnchant` / `weaponDamageBonus` are pure.
- **Potion registry** — 10 canonical potions with effect entries; `drinkPotion` applies effects to a sink. 10 brewing recipes (awkward + glistering melon → healing etc.) matching MC.
- **Villager trade logic** — 5 professions (farmer / librarian / blacksmith / butcher / fletcher / none) with base offers resolved via a name→itemId map at spawn; `executeTrade` locks offers at maxUses; `villagerLevelUp` unlocks on XP thresholds.
- **Anvil combine** — repair damaged tool, rename, merge enchants with level-increment-on-match rule and `maxLevel` cap. XP cost tracked.

## Cut / deferred (to Post-M12 backlog)

- **Enchantment table + brewing stand + anvil blocks and UI** — the logic modules ship pure and unit-tested, but placing the blocks and wiring a DOM panel is a separate piece of work.
- **Villager Mob entity** (profession-coloured renderer + wandering + trade UI).
- **Bookshelf power weighting** for enchantment rolls.

## Biggest surprise

Splitting every system into a pure-logic module (`enchantment.ts`, `potion.ts`, `anvil.ts`, `villager.ts`) made each one independently testable and let me ship all four in one iteration without any rendering / UI / block-entity infrastructure. The integration (blocks, panels, entity spawning) has genuine complexity that doesn't reduce to unit tests, so keeping it for later is the right trade. 304 tests, green on first full CI.

## What the next milestone should know

- **Potion `applyEffect` contract** takes an amplifier (0-indexed: `amp=0` is the "I" tier, `amp=1` is "II"). Matches MC's internal representation — don't convert at the boundary.
- **Villager trades use a name-based offer table** resolved at spawn time; adding a new profession means listing its offers + passing a registry resolver at spawn.
- **Anvil extends `Enchanted`**, which extends `ItemStack`. Anything that handles ItemStack should treat the extra fields (enchants, name) as optional and preserve them through round-trips.
- **XP curve is the authoritative formula** — don't reimplement. Import `xpToNext` if you need level budgeting (e.g., anvil caps at 39 XP levels in MC).
