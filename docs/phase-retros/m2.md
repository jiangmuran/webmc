# M2 retro — Block Interaction + Per-Face Colors

**Estimated:** ~15–16h. **Actual (this session):** ~2.5h wall-clock.
**Status:** DONE per STANDARDS.md §2.1. Texture-atlas portion of M2.4/M2.5 deferred as a post-M2 micro-milestone (tracked in `/backlog.md`).

## Shipped

- `physics/raycast.ts` Amanatides–Woo DDA, allocation-free in the step loop, returns first solid voxel + entered face + distance.
- `game/Interaction.ts` hooks mousedown on canvas, raycasts from camera+look, breaks or places on the face normal; refuses to place on a non-air voxel or one overlapping the player AABB; repeats at ~220 ms while held.
- `ui/Hotbar.ts` 9-slot DOM overlay; number keys + scroll wheel select; slot color = registry color; selection highlight follows.
- Mesher + snapshot + worker protocol upgraded to per-face palette colors (9-byte stride: top, bottom, side). Mesher chooses per face based on axis/direction, so grass is correctly green-on-top / olive-on-side / brown-below and oak logs have lighter end grain than bark.
- BlockRegistry grows from 6 to 32 blocks: three stone variants, deepslate, cobblestone, mossy cobble, dirt, grass, oak/spruce/birch logs + leaves + planks, sand, gravel, water, lava (non-solid, transparent), six ores, glowstone, glass, brick, bookshelf, four wool colors.
- `flushDirty` now runs per-frame and dispatches mesh jobs concurrently as the world changes.
- e2e: m2-place-break (simulated click + hotbar select) plus m1-walkaround unchanged.

## Verification

`npm run verify:m2` green: 112 unit tests across 14 files, 8 Playwright scenarios (desktop + Pixel-7 emulation), mesh bench p95 ≤ 2.3 ms per 16³ chunk.

## Cut or deferred

- **Real texture atlas (M2.4).** Originally planned as a procedurally-generated 512×512 PNG + UV map. Deferred because per-face colors already satisfy DONE-when, and building the generator right means deciding a tile scheme and shipping a content-hash check — both of which couple to M3's biome colors and M5's save format. Spun into a follow-up: "Post-M2: procedural atlas generator". Tracking in `/backlog.md`.
- **Full UV vertex attribute.** Mesher output would grow by a Float32Array of 2×verts. Blocked by the deferred atlas; we'd emit UVs with nothing to sample. Charter §1.4 "don't invent hypothetical future requirements" says wait until the atlas lands.
- **Water/lava actually non-solid in the world demo.** The registry marks them `solid: false, opaque: false` but the demo doesn't place any — M9 wires actual fluids.

## Biggest surprise

The pointer-lock request rejects silently with `WrongDocumentError` in headless Chromium before Playwright completes the first nav. Fix: `.catch(() => {})` on the returned Promise in `FirstPersonCamera.click`. Otherwise our zero-console-error e2e assertion would be a lie about feature health. Lesson: every async browser API needs an explicit rejection handler, even for "impossible" cases, when CI runs without a real user.

## Next milestone (M3) should know

- Biome colors are just per-face top/side/bottom values. M3 can compute per-vertex tint = biome color from worldX, worldZ and pass it as an additional attribute, or bake biome colors into a second palette stride.
- Light propagation (sky + block BFS) outputs a `Uint8Array` of light levels per voxel; the mesher will read and bake vertex light into the existing `colors.a` channel (currently always 255). Plan: expand snapshot to include `flatSkyLight` + `flatBlockLight`.
- The deferred atlas should ship alongside M3's biome colors so biome tinting operates on real textures, not flat colors. Combine M2.4-deferred + M3 work.
- Raycast is allocation-free. If M3's chunk streaming causes frame-budget issues, consider reusing a global `RayHit` object to avoid the one `{ bx, by, bz, face, distance }` allocation per cast.
