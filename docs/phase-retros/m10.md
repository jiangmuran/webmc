# M10 — Caves, Ores, Structures (Retrospective)

## Shipped

- **3D noise cave carving** — `Perlin.fbm3` + `WorldGenerator.isCave` carve caves in y∈[2,60] where |fbm3|<0.32. Produces connected cave networks (not isolated pockets) because the threshold forms a continuous isosurface.
- **Deepslate layer** — y≤4 stone → deepslate (hardness 3, matching MC's 1.20 deepslate layer at bedrock).
- **Ore distribution** — 6 ores (coal / iron / gold / diamond / redstone / lapis) placed on triangular Y-band density curves:
  - coal peak y=55, width 45 (surface-facing)
  - iron peak y=20, width 30
  - gold peak y=14, width 18
  - redstone peak y=8, width 14
  - lapis peak y=14, width 16
  - diamond peak y=5, width 10 (deepest, rarest)
- **Dungeon rooms** — 1/30 per-chunk deterministic gate places a 5×5×4 hollow cobblestone / mossy-cobble shell in y∈[12,50].
- **Tests** — unit coverage for cave carving (non-trivial air count), ore distribution (diamond deep, coal shallow), deepslate placement, dungeon presence across a 9×9 chunk scan, and determinism across all new features.

## Cut / deferred

- **Mineshafts (M10.5)** and **villages (M10.6)** — both need a cross-chunk structure coordinator that doesn't exist yet. Per-chunk determinism works for dungeons (single chunk shell) but not for 100-block-long rail tunnels or multi-building settlements.
- **Dungeon spawner + chest loot** — rooms are empty shells; mob-spawner tile-entity and chest loot tables deferred to M11 when the mob system expands.
- **Ravines** — deferred; their elongated-axis noise warp is a second full pass on every chunk.

## Biggest surprise

Cave carving "just worked" because noise is inherently continuous across chunk borders — no BFS stitching needed as long as every chunk samples the same noise function at the same world coordinates. The original fear was that independent per-chunk generation would produce disconnected cave pockets; it produced the opposite, caves that sprawl organically. The real caveat is that caves carve AIR into already-generated stone, which means chunks generated at different times (via streaming) always produce identical results for the same seed because the generator is pure.

## What the next milestone should know

- **`oreAt(wx, wy, wz)`** is pure and deterministic — callable at any point for e.g. loot-table-style mining. It short-circuits above y=70.
- **Dungeon placement** uses `hash32(cx, cz, seed ^ DUNGEON_SALT)` — changing DUNGEON_SALT moves every dungeon in the world. Stable.
- **`isCave`** returns TRUE only in y∈[2,60]. Above y=60 caves are absent by design (MC has surface caves via a different noise band; we haven't implemented that yet).
- **Mesher impact** — caves and dungeons produce many more AIR transitions, raising greedy-quad count per chunk. Bench has not been re-measured for regression; keep an eye on mesh time if M11 adds mob-heavy gameplay.
