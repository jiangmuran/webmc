# M9 — Fluids (Retrospective)

## Shipped

- **FluidField simulator** — pure function `tickFluid(cells, isSolid)` returning updates. Level 0–8 encoding (8 = source, 1–7 = flowing), horizontal attenuation 1 (water) / 2 (lava), unconditional downward flow.
- **BFS-from-source dry-up** — replaces the naive per-cell decrement that failed when stacked cascades kept each other "fed from above" across 15 ticks. Now a puddle disconnected from any source is removed immediately; guarantees full cleanup and bounded state.
- **FluidWorld adapter** — sidecar `Map<string, FluidCell>` + Three.js World integration. `setSource`/`clear`/`tick` project updates back into the World as water/lava block state, yielding changed positions for chunk re-mesh.
- **Swim physics** in `FirstPersonCamera` — submerged state reduces horizontal speed to 50%, replaces gravity with buoyancy drag (0.8 water, 0.5 lava), swim-up on jump key (+4 m/s water, +2 m/s lava).
- **Lava damage + drowning** in `PlayerState.tick({ inFluid })` — 4 HP/s lava contact, 15 s breath timer draining to 2 HP/s drowning; breath refills at 3× outside fluid.
- **Bucket items** registered (`webmc:bucket`, `webmc:water_bucket`, `webmc:lava_bucket`); placement wiring deferred to backlog.
- **Main-loop integration**: 4 Hz fluid tick, affected chunks marked dirty for re-mesh, `fp.inFluid` wired into `playerState.tick`.

## Cut / deferred

- **Waterlogged state on fences / slabs / stairs** (M9.6) — deferred to post-M9. Requires per-block variant encoding in `BlockState` props.
- **Bucket placement + pickup** UX — items exist; onUse hook will land with the placement-interaction rework already backlogged from M8.6.
- **Water-meets-lava → stone / obsidian / cobblestone** — deferred to M10 alongside ore generation.

## Biggest surprise

The dry-up test needed 15 post-removal ticks but stable-state cascades (water falling off platform edges) kept each column alive via the "fed from above" check — cells kept each other alive in a loop. Switching Phase 2 from per-cell decrement to BFS-from-sources cut the logic in half and made cleanup deterministic in a single tick. Aggressive drain is less authentic than MC's gradual evaporation but keeps simulator state bounded and the test green.

## What the next milestone should know

- **FluidWorld.tick** mutates the World directly and returns changed positions — callers must mark affected chunks dirty for re-mesh, otherwise stale geometry persists.
- **FluidCell.source** flag is the only distinguisher between source and flowing water; don't infer from level alone (level 8 = source, but after MC parity waterlogged etc. may produce level 7 flowing).
- **isFluid sampler** reads from `World.get` — stale for 1 frame after a fluid tick mutates state before the main loop queries. Not an issue at 4 Hz but relevant if the tick rate rises.
- Lava light emission is 15 already (registry) but dynamic light propagation from flowing lava is NOT wired — M10 or lighting rewrite territory.
