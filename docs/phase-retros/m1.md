## Biggest surprise

Three.js `ShaderMaterial` silently prepends `attribute vec3 position; attribute vec3 normal; uniform mat4 modelViewMatrix; ...` to the vertex shader. My shader redeclared them and WebGL refused to compile it — Three's error surface was a long wall of log. The fix is to just drop those redeclarations from the user shader; they are available as-if-declared. Added a comment upstream. This will matter again when M3's lighting shader or M16's WebGPU port is written.

Second surprise: TypeScript with `noUncheckedIndexedAccess` makes mesher-style code noisy (every `arr[i]` is `T | undefined`). Switching from 3-tuple arrays to flat scalar locals (`ox, oy, oz`) both fixed the noise and plausibly helped V8 inline the hot loop.

## Next milestone (M2) should know

- Per-face UVs and a procedural atlas will plug in by enlarging the color attribute to include `uOff`/`vOff`, or by adding a second `vec2` attribute. The mesher already walks faces in a known winding order (s=1 CCW, s=0 CW); atlas per-face tile index can be emitted alongside the color.
- `BlockDef.color` placeholder stays for non-atlased blocks until the atlas covers everything.
- The mesher is the single biggest M2 touchpoint — the atlas is ultimately a one-attribute change plus a shader swap. Don't refactor the chunk storage yet; it's shaped right for M2–M5.
- `isSolid`/`isOpaque` closures in main.ts look up registry per voxel — fine for now, but if M3's lighting BFS or M10's flood needs many cell lookups, cache a per-palette `Uint8Array` of opacity flags like the mesher already does.
- The local Clash proxy footgun (M0) reappears whenever we add a new local service (M6 signaling is next). Apply the same `no_proxy` + `--proxy-server=direct://` combo then.
